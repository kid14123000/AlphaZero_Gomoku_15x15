# value 目标切到 q 软标签（2026-11-15 07:34）

> 这一页只记「改了什么、为什么、怎么验、怎么退」。判据阈值一律不动，与
> `README_15x15.md` §2026-11-14 21:30 那一段保持一致。

## 1. 改动一句话

`--value_target` 从 **`z`（终局胜负 ±1 硬标签）** 换成 **`q`（MCTS 根搜索价值软标签）**。
代码支持早已在仓里（`58508ce` 加 q、`e69da59` 修符号、`94ba051` 加符号自检），
**本次没有改训练代码**，只是启动参数换档 + 把启动脚本补齐。

## 2. 两种标签的差别（代码事实）

| | `z`（原） | `q`（现） |
|---|---|---|
| 目标值 | 终局 `win=+1 / lose=-1`（`game.py:250-256`） | MCTS 根节点 Q（`mcts_alphaZero.last_root_q`，`get_move_probs` 内已取负 ⇒ **该走方视角**） |
| 取值范围 | 只有 ±1 两个点 | `[-1, 1]` 连续，能区分「险胜 / 碾压」 |
| 批内方差 | `var(z)≈0.98`（≈满幅） | 明显更小，`value_loss` 上限随之下降 |
| 梯度 | 每个样本都推满幅 | 按「这一手到底多好」加权 |
| 风险 | 把 1 目险胜和 20 手碾压当同一目标 ⇒ 逼 value 头当预言家 | Q 本身有噪声；若搜索价值无信号（Q 全贴 0）等于教 value 头「两边不靠」 |
| `mix` 档 | — | `t = 0.5·q + 0.5·z`（`mix_lambda=0.5`），用作中间退路 |

**为什么换**（与既有结论一致）：±1 是「不可学的目标」，软标签只学可学的部分。
`q` 直接来自 MCTS 访问分布对应的根价值，跟 policy 标签同一次搜索，口径自洽。

## 4. 🚨 两个必须知道的坑

### 4.1 `resume.sh` 原本会把 q **静默退回** z

`train.py` 的 `--value_target` **argparse 默认是 `z`**。`resume.sh` / `run_15x15.sh`
原来都不传这个参数 ⇒ 一旦续训，配置就悄悄变回 ±1 硬标签，日志里只有一行 start 记录，
曲线不会报错，只有 value 指标慢慢不对。

已修：两个脚本都改成 `--value_target "${VALUE_TARGET:-q}"`，并且 `resume.sh`
开跑横幅会打印 `value 目标 : q`。要退回硬标签不用改文件：

```bash
VALUE_TARGET=z ./resume.sh          # 退回 ±1
VALUE_TARGET=mix ./resume.sh        # 折中：q/z 各半
N_PLAYOUT=400 ./resume.sh           # 想改模拟数（默认已对齐 800）
```

同时把 `resume.sh` 里过期的 `--n_playout 400` 对齐成 `800`（README 写死「800 全程不变」，
用 400 续训会让新旧数据分布不可比）。

### 4.2 局号与 z 段重叠 59 局

- z 段：`batch_offset 14217`，实际跑到 **15809**（1592 局），归档在
  `~/archive/v4_run1_logs_1115_0718/`

⇒ **15751–15809 这 59 个局号在两条段里各有一局，内容不同**。
统计时一律按 `start` 记录切段，别把两份 `metrics.jsonl` 直接拼起来算。

## 5. 验证：现在只能验「配置生效」，验不了「行为生效」

| 层级 | 手段 | 现状 |
|---|---|---|
| 配置 | `logs/metrics.jsonl` 首行 `start.value_target == "q"` | ✅ 已核对 |
| 符号 | `_selfcheck_q_sign()`：构造「黑四连、落子即成五」局面，根 Q 必须显著为正，反了**拒绝启动** | ✅ 有自检（`train.py:176-200`），本次启动成功 ⇒ 符号正确 |
| 行为指纹 | `q_mean / q_std / q_absmean / t_mean / t_std` | ❌ **算出来了但没写进日志** |

🚨 **已知缺口**：`train.py` 在替换 value 目标时算好了 `q_stats`（`train.py:274-279`），
但 `metrics.log('update', ...)` 那一段（`train.py:464-479`）**没把它带上**，
所以 `metrics.jsonl` 的 update 记录里没有 Q 分布。后果：

- 无法判断「Q 真的有信号」还是「Q 贴在 0 附近」（代码注释自己写了这条判据：
  均值与标准差都贴近 0 ⇒ 搜索价值没信号 ⇒ 该退 `mix` 或 `z`）
- 无法用行为指纹证明 value 头在学软标签，而不是仍在学 ±1

**建议**（需点头才动 `train.py`，纯加日志、不改任何训练行为）：把 `q_stats` 的五个字段
一起写进 update 记录。这样下一次重启后就能一眼看出 Q 有没有信号。

## 6. 判据（先定死，不事后挪）

沿用主判据不变：**白胜 ≥20%（近 100 局）+ 均手 ≥24 + 速杀≤11 手 <15%**。

q 段 **专项判据**（窗口 = 3 次发行版本 ≈120 局，从 15751 起）：

- ✅ 有价值：`ev_new` 不低于 z 段**末段实测 0.659** 的 −0.05（即 ≥0.61），且 loss 均值不超过 2.9
- ⚠️ 无信号：`q_absmean` 长期 <0.15（Q 都贴 0）⇒ 退 `mix`
- ❌ 变差：`ev_new` 持续 <0.60 或 `ev_old` 跌破 0.45（z 段末段 0.521）⇒ 直接退 `z`，别硬跑
