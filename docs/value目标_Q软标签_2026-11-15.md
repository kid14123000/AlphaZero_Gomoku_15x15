# value 目标切到 q 软标签（2026-11-15 07:34）

> 这一页只记「改了什么、为什么、怎么验、怎么退」。判据阈值一律不动，与
> `README_15x15.md` §2026-11-14 21:30 那一段保持一致。

## 1. 改动一句话

`--value_target` 从 **`z`（终局胜负 ±1 硬标签）** 换成 **`q`（MCTS 根搜索价值软标签）**。
代码支持早已在仓里（`58508ce` 加 q、`e69da59` 修符号、`94ba051` 加符号自检），
**本次没有改训练代码**，只是启动参数换档 + 把启动脚本补齐。

## 2. 两种标签的差别（代码事实）

| | `z`（原） | `q`（现） |
|---|---|---|
| 目标值 | 终局 `win=+1 / lose=-1`（`game.py:250-256`） | MCTS 根节点 Q（`mcts_alphaZero.last_root_q`，`get_move_probs` 内已取负 ⇒ **该走方视角**） |
| 取值范围 | 只有 ±1 两个点 | `[-1, 1]` 连续，能区分「险胜 / 碾压」 |
| 批内方差 | `var(z)≈0.98`（≈满幅） | 明显更小，`value_loss` 上限随之下降 |
| 梯度 | 每个样本都推满幅 | 按「这一手到底多好」加权 |
| 风险 | 把 1 目险胜和 20 手碾压当同一目标 ⇒ 逼 value 头当预言家 | Q 本身有噪声；若搜索价值无信号（Q 全贴 0）等于教 value 头「两边不靠」 |
| `mix` 档 | — | `t = 0.5·q + 0.5·z`（`mix_lambda=0.5`），用作中间退路 |

**为什么换**（与既有结论一致）：±1 是「不可学的目标」，软标签只学可学的部分。
`q` 直接来自 MCTS 访问分布对应的根价值，跟 policy 标签同一次搜索，口径自洽。

### 5.2 🚨 已观测到的事实：Q 几乎是饱和的

补日志前，主进程每 25 局已经会往 stdout 打一行 Q 分布（`logs/train_v4_curriculum.log`）：

| 局号 | q_mean | q_std | **q_absmean** |
|---|---|---|---|
| 15751 | +0.1210 | 0.9266 | **0.9319** |
| 15776 | +0.0247 | 0.9436 | **0.9434** |
| 15801 | +0.0662 | 0.9753 | **0.9772** |
| 15826 | +0.1161 | 0.9148 | **0.9202** |

队列里未消费的 npz 抽查（`queue/001794699131734_7_5.npz`，132 手）：
`mean −0.0082 / std 0.8499 / absmean 0.8257`。

**结论（推断）**：`|Q|` 均值 **0.83~0.98**，而 z 恒为 1.0。也就是说 **q 软标签只比 ±1 硬标签软了一点点** ——
自对弈里网络对自己的局面非常"确定"（胜负分明），根 Q 基本贴在 ±1 附近。
所以「z→q 能区分险胜/碾压」的理论收益，**在这批数据上大部分不成立**。

这不是 bug，是数据性质：只有当对局本身胶着（一半的局面 Q 在 0.3~0.7）时软标签才有额外信息量。
**判据据此调整**（写死，不事后挪）：若 `q_absmean` 持续 >0.90，则 q 与 z 等价，
本段跑完 120 局后应比较 `ev_new` 是否真有差异；差异 <0.02 就判定「换档无效」，退回 z 或改 `mix`。

### 9.2 🚨 混杂源：重启丢了 `init_lr_multiplier`

启动命令（`ps -o command=` 实读）**没有 `--init_lr_multiplier`**，于是取默认 **1.0**；
而 z 段稳态是 **0.0878**（12 倍差距）。同时 value 目标从 z 换成 q。双重冲击的实测后果：

| update | lr_multiplier | KL | loss | policy 熵 |
|---|---|---|---|---|
| 15755（首更） | **0.667** | **1.8493** | 2.882 | 2.250 |
| 15756 | 0.444 | 0.3714 | **4.199** | **3.106** |
| 15758 | 0.296 | 0.1224 | 3.757 | **4.093** ← 逼近均匀 ln225=5.416 |
| 15760 | 0.198 | 0.0859 | 3.460 | 3.651 |
| 15761 | 0.132 | 0.1651 | 3.144 | 3.148 |
| 15767 | 0.088 | 0.1237 | 3.082 | 2.961 |
| 15773 起 | 0.088 | 0.05 | 2.887 | 2.524 |

**首更 KL=1.85 是灾难级的**：policy 被大幅打散，熵从 2.25 冲到 4.09，用了 **6 次 update（≈40 局）**
才把 lr 压回 0.088、熵拉回 2.5。也就是说 **q 段前 ~40 局是一个被打伤的网络上打的**，
拿它跟 z 段稳态跑出来的 16.9% 比，比的是"重伤 vs 健康"，不是"q vs z"。

### 9.3 顺带修正我自己的一条错判据

第 6 节原写「q_absmean 持续 >0.90 则 q≈z，比 ev_new 差异 <0.02 判无效」。
**ev 在换档后根本不可比**：`train.py:446-451` 的
`ev = 1 − var(winner_batch − v)/var(winner_batch)` 里 `winner_batch` 就是训练目标本身，
换档后**分子（残差对 q）和分母（var(q)）同时变了**。实测 q 段 `ev_new 0.659` vs
z 段末段 `0.659`，数字巧合相同，但**不能当作"一样好"**。

可比的只有行为指标（白胜/均手/速杀）和训练动力学（KL/熵）。

## 10. 副产品：回放页逐步胜率改用 qs（2026-11-15 08:5x）

q 软标签要求 worker 逐手采根 Q，这份数据本来只在 `queue/*.npz` 里、被主进程吃完就删。
既然要长期保留，顺手接到回放页：

- `parallel_train.py`：写 `games.jsonl` 时带上 `qs`（4 位小数）
- `web/engine.py::q_series_from_qs()`：把 `qs` 拼成与 `game_value_series` 同构的序列
- `/api/games/detail`：**优先 qs**，没有才回落到干净前向，并返回 `values_source`
- 回放页：显示来源标签；qs 来源下数值卡显示「根 Q」而不是「网络先验/首选」

**为什么这个比现算好**：现算用的是**现在**的权重（可能是几十代之后），反映的是"今天怎么看当年这手"；
qs 是**当时**那副权重 + 800 次模拟给出的判断，是真正驱动那一手的依据。两者用途不同，
现在页面默认给后者，"判断力对比"那个功能仍然保留前者（可换任意 ckpt 重算）。

**成本**：省掉每局 0.6 秒前向；代价是 `games.jsonl` 每局多约 200 字节。
