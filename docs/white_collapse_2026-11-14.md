# 白崩事件记录（2026-11-14）

一次在「改对搜索结构之后 120 局内发生」的白棋崩溃。留档给以后：症状长什么样、怎么在 30 分钟内定位、哪些指标会骗人。

## 一句话

把 Dirichlet 噪声从「落子抽样」搬到「根节点先验」+ `c_puct` 5→1.25 之后，前 131 局健康（白胜 34%→31%→64%，均手 24~30），第 133 局起白棋崩掉（白胜 2%），同时 **loss 下降、价值头解释方差升到 0.94** —— 所有"常规训练指标"都朝好的方向走。

## 排查过程（按顺序，每步都留了工具）

### 1. 先排除权重数值损坏

5 个 checkpoint 扫描：非有限张量 0 个，‖W‖ 从 256,369 缓慢爬到 263,402，`max|w|` 从 12,723 到 13,074。属于正常漂移，没有爆炸。

### 2. 按权重版本拆数据，定位到 ver3

不分版本看是"整体白胜 20% 还能接受"，一分版本就成了"ver0-2 健康、ver3 起直接归零"。**这一步是整次排查里最关键的**：滚动平均会把 40 局一个版本的突变抹平。

### 3. 对称性探针

同一个等价盘面（180° 旋转 + 黑白互换），只改变"轮到谁走"：

```
白走（原盘面）     value = -0.8222
黑走（旋转+换色）  value = -0.4866
|Δv| = 0.3356
```

同一个局面对不同执色给出差 0.34 的评估。value 头在拿"我执什么色"当胜负证据。

### 4. c_puct 敏感性探针（否定了一个假说）

怀疑是不是 `c_puct` 5→1.25 单独造成的。构造 4 个「黑已成型、白必须堵」的局面，800 模拟，只改 c：

```
防守成功        c=1.25 → 0/4      c=5 → 0/4
平均已访问子节点  219.0            219.0
平均访问熵        3.33             3.21
top1 访问占比     0.36             0.38
平均 Q 跨度       0.029            0.047
```

**4 个局面选点完全相同。** c_puct 在这次崩溃里不是变量。

### 5. 为什么 c_puct 失效 —— 真正的原因

探针顺手测出了答案：

```
根 Q = -0.992
已访问子节点的 Q 区间 = [-1.000, -0.942]，跨度 0.029
```

白方搜索里所有走法的 Q 都是 -0.99 左右。PUCT 的打分是

```
Q + c_puct · P · sqrt(N_parent) / (1 + N_child)
└┬┘   └────────── 只跟先验 P 和访问数有关 ──────────┘
全一样
```

Q 没有区分度时，排序完全由先验 P 决定，`c_puct` 只能整体缩放同一项，改不了次序。**所以 MCTS 参数在 value 饱和的局面上一个都救不了。**

再看具体一手（黑冲四，白唯一堵点是 (7,4)）：

```
c=1.25: (r7,c9) 267 访问   (r7,c4) 140 访问
                  ↑先验第一     ↑唯一活命的点
```

搜索给了正确堵点 140 次访问，说明搜索没瞎，是**先验把这个点排在后面**，而 Q 全都一样没法纠正。

## 根因链条

```
value 头把「执黑」当胜负证据（ch3 是执黑常量，网络能直接读出）
        ↓
白方局面 Q 全饱和到 -0.99
        ↓
PUCT 退化为「纯按先验排序」，c_puct 失效
        ↓
白方按错误先验落子，不堵主线
        ↓
黑速胜（≤11 手 38%），局长 29.7 → 17.7
        ↓
黑速胜样本进 buffer，value 学到「黑赢」
        ↓
loss ↓、ev_new ↑（预测得更准了，因为比赛变简单了）
        ↓
回到第一行，正反馈
```

## 为什么这次崩得比历史快

历史记录：v24 约 2200 局白崩、v40 约 1400 局。这次 **120 局**。

推断（未验证）：噪声进了根先验之后，搜索真的会去探索；value 已经偏负时，多探到一条"我要输"的分支，白方就更早确认自己必输。同一条正反馈，以前噪声只摇最后一手、搜索里无从体现，现在能闭合了。

## 白胜局的质量

崩盘中白胜的 59 局里：

```
白胜局：均手 27.8  中位 26   34% 超过 28 手   最长 68 手
黑胜局：均手 22.8  中位 23   28% 是 ≤17 手速杀
```

白赢的局比黑赢的局**长 5 手**。如果白只是靠"黑速攻自己走歪"捡胜，白胜局应该更短。实际更长，说明白在长局里防住了再反打——**白是"局部崩"（中盘被速攻），不是"全线废"**。

这条是判断"能不能自己回来"的关键量，比白胜率本身灵敏。

## 判据与预案（崩盘当天定死，事后不改）

观察窗口：3 个权重版本（约 120 局）。

| 结论 | 条件 |
|---|---|
| 回来了 | 白胜率 ≥ 20%，**或**空盘 value ≤ +0.60 |
| 没回来 | 120 局后白胜仍 < 10%，**且**空盘 value 仍 > +0.70 |
| 立即停训 | 空盘 value 重新爬回 +0.95，且白胜率回到 0~2% |

回滚点定为 `ckpt_it13552`（ver2 前最后一个健康版本，白胜 64%、空盘 value +0.299）。

## 能提前预警的指标

| 指标 | 崩盘时表现 | 能不能当警报 |
|---|---|---|
| loss | 3.13 → 2.72（**降**）| ✗ 反向 |
| ev_new | 0.745 → 0.941（**升**）| ✗ 反向 |
| 策略熵 | 2.88 → 2.66（缓降）| ✗ 太钝 |
| 白胜率（分版本）| 34% → 2% | ✓ 但滞后 1~2 个版本 |
| **空盘 value** | +0.30 → **+0.97** | ✓ **唯一提前亮红的量** |

空盘没有一颗棋子。网络说黑胜 97%，那它读的就不是局面，而是「我执黑」这个身份。这个量在崩盘正式发生前就已经飙起来了，而且不会跟着 loss 一起变好看。

`sentinel.py` 就是按这个指标做的外部哨兵：只读 `sync/current_policy.model`，跑一次空盘前向 + 统计最近 60 局，追加到 `logs/sentinel.txt`。不改训练代码、不重启、不占核。

## 教训

1. **滚动平均会藏住 40 局一个版本的突变。** 判读必须先按 `net_version` 分组。
2. **loss 和解释方差在白崩时是反向指标。** 崩盘让局面变简单，预测自然变准。看到"指标全面向好 + 行为变短"要按警报处理。
3. **value 饱和会让所有 MCTS 参数失效。** 调 `c_puct`、调温度之前，先测根 Q 的跨度；跨度 < 0.05 时搜索已经名存实亡。
4. **`ch3`（执黑常量）是这个架构的偏色入口。** 网络能直接读出自己执黑执白，这是「身份捷径」的结构性来源。真要治本得改输入语义、从零重训，不在这一轮做。
