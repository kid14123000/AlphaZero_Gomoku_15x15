# 白崩事件记录（2026-11-14）

一次在「改对搜索结构之后 120 局内发生」的白棋崩溃。留档给以后：症状长什么样、怎么在 30 分钟内定位、哪些指标会骗人。当天下班前换了一版分层采样的训练逻辑，前半段速杀率砍半、白胜率没动，还在观察窗口里——最后一节。

## 一句话

把 Dirichlet 噪声从「落子抽样」搬到「根节点先验」+ `c_puct` 5→1.25 之后，前 131 局健康（白胜 34%→31%→64%，均手 24~30），第 133 局起白棋崩掉（白胜 2%），同时 **loss 下降、价值头解释方差升到 0.94** —— 所有"常规训练指标"都朝好的方向走。

后续处理是给训练样本加分层采样（白赢样本独立储库 + 按白率动态调份额），不是修搜索参数。机制、前 93 局实测、以及为什么"白胜率没涨但速杀砍半"已经算部分有效，见「解法：分层采样 + 白赢储库」。

## 排查过程（按顺序，每步都留了工具）

### 1. 先排除权重数值损坏

5 个 checkpoint 扫描：非有限张量 0 个，‖W‖ 从 256,369 缓慢爬到 263,402，`max|w|` 从 12,723 到 13,074。属于正常漂移，没有爆炸。

### 2. 按权重版本拆数据，定位到 ver3

不分版本看是"整体白胜 20% 还能接受"，一分版本就成了"ver0-2 健康、ver3 起直接归零"。**这一步是整次排查里最关键的**：滚动平均会把 40 局一个版本的突变抹平。

### 3. 对称性探针

同一个等价盘面（180° 旋转 + 黑白互换），只改变"轮到谁走"：

```
白走（原盘面）     value = -0.8222
黑走（旋转+换色）  value = -0.4866
|Δv| = 0.3356
```

同一个局面对不同执色给出差 0.34 的评估。value 头在拿"我执什么色"当胜负证据。

### 4. c_puct 敏感性探针（否定了一个假说）

怀疑是不是 `c_puct` 5→1.25 单独造成的。构造 4 个「黑已成型、白必须堵」的局面，800 模拟，只改 c：

```
防守成功        c=1.25 → 0/4      c=5 → 0/4
平均已访问子节点  219.0            219.0
平均访问熵        3.33             3.21
top1 访问占比     0.36             0.38
平均 Q 跨度       0.029            0.047
```

**4 个局面选点完全相同。** c_puct 在这次崩溃里不是变量。

### 5. 为什么 c_puct 失效 —— 真正的原因

探针顺手测出了答案：

```
根 Q = -0.992
已访问子节点的 Q 区间 = [-1.000, -0.942]，跨度 0.029
```

白方搜索里所有走法的 Q 都是 -0.99 左右。PUCT 的打分是

```
Q + c_puct · P · sqrt(N_parent) / (1 + N_child)
└┬┘   └────────── 只跟先验 P 和访问数有关 ──────────┘
全一样
```

Q 没有区分度时，排序完全由先验 P 决定，`c_puct` 只能整体缩放同一项，改不了次序。**所以 MCTS 参数在 value 饱和的局面上一个都救不了。**

再看具体一手（黑冲四，白唯一堵点是 (7,4)）：

```
c=1.25: (r7,c9) 267 访问   (r7,c4) 140 访问
                  ↑先验第一     ↑唯一活命的点
```

搜索给了正确堵点 140 次访问，说明搜索没瞎，是**先验把这个点排在后面**，而 Q 全都一样没法纠正。

## 根因链条

```
value 头把「执黑」当胜负证据（ch3 是执黑常量，网络能直接读出）
        ↓
白方局面 Q 全饱和到 -0.99
        ↓
PUCT 退化为「纯按先验排序」，c_puct 失效
        ↓
白方按错误先验落子，不堵主线
        ↓
黑速胜（≤11 手 38%），局长 29.7 → 17.7
        ↓
黑速胜样本进 buffer，value 学到「黑赢」
        ↓
loss ↓、ev_new ↑（预测得更准了，因为比赛变简单了）
        ↓
回到第一行，正反馈
```

## 为什么这次崩得比历史快

历史记录：v24 约 2200 局白崩、v40 约 1400 局。这次 **120 局**。

推断（未验证）：噪声进了根先验之后，搜索真的会去探索；value 已经偏负时，多探到一条"我要输"的分支，白方就更早确认自己必输。同一条正反馈，以前噪声只摇最后一手、搜索里无从体现，现在能闭合了。

## 白胜局的质量

崩盘中白胜的 59 局里：

```
白胜局：均手 27.8  中位 26   34% 超过 28 手   最长 68 手
黑胜局：均手 22.8  中位 23   28% 是 ≤17 手速杀
```

白赢的局比黑赢的局**长 5 手**。如果白只是靠"黑速攻自己走歪"捡胜，白胜局应该更短。实际更长，说明白在长局里防住了再反打——**白是"局部崩"（中盘被速攻），不是"全线废"**。

这条是判断"能不能自己回来"的关键量，比白胜率本身灵敏。

## 判据与预案（崩盘当天定死，事后不改）

观察窗口：3 个权重版本（约 120 局）。

## 能提前预警的指标

| 指标 | 崩盘时表现 | 能不能当警报 |
|---|---|---|
| loss | 3.13 → 2.72（**降**）| ✗ 反向 |
| ev_new | 0.745 → 0.941（**升**）| ✗ 反向 |
| 策略熵 | 2.88 → 2.66（缓降）| ✗ 太钝 |
| 白胜率（分版本）| 34% → 2% | ✓ 但滞后 1~2 个版本 |
| 空盘 value | +0.30 → **+0.97** | ✓ 能抓"执色偏置"这一类，见下方限定 |

空盘没有一颗棋子。网络说黑胜 97%，那它读的就不是局面，而是「我执黑」这个身份。这个量在崩盘正式发生前就已经飙起来了，而且不会跟着 loss 一起变好看。

**限定（后来补的）**：空盘 value 只对「网络把执黑当成身份捷径」这一条路径敏感。同一轮崩盘里还有第二种形态——网络空盘 value 停在 +0.33（完全正常），白棋却已经在必堵局面放弃防守。这一类的检验在盘面上，不在空盘上。所以"唯一提前亮红的量"这个说法是错的，得收窄成"覆盖一类"。下面「解法：分层采样」一节给了不依赖空盘的第二条早期信号。

`sentinel.py` 就是按这个指标做的外部哨兵：只读 `sync/current_policy.model`，跑一次空盘前向 + 统计最近 60 局，追加到 `logs/sentinel.txt`。不改训练代码、不重启、不占核。

## 解法：分层采样 + 白赢储库

崩盘当天下午换了一版训练逻辑，`parallel_train.py` 的 argv 多了 `--handicap_file sync/handicap.json`，旁边多跑一个 `curriculum_ctl.py`。这版不算修 bug，算改数据配比——前面几节的所有结论都留着，只是给采样加了一层约束。

### 它做什么

训练样本按「谁在走 × 谁赢」分成四类：

```
0 = B_win   黑方走，黑赢
1 = B_lose  黑方走，黑输
2 = W_win   白方走，白赢     ← 崩盘时要抬的就是这一类
3 = W_lose  白方走，白输
```

标签在 `train.py` 的 `collect_selfplay_data` 里按手数奇偶打上去（`_mover = 1 if _i % 2 == 0 else 2`，第 0 手黑走），跟着 8 重对称增广一起进 buffer。抽样时不再从整池随机抽，而是按目标份额分四层抽，份额由控制器按白率写盘：

| tier | 触发条件 | B_win | B_lose | W_win | W_lose |
|---|---|---|---|---|---|
| collapse | 白率 < 20% | 0.35 | 0.10 | **0.22** | 0.33 |
| mid | 20% ~ 35% | 0.40 | 0.09 | 0.16 | 0.35 |
| healthy | 白率 > 35% | 0.44 | 0.08 | 0.10 | 0.38 |

`B_win` 在任何档都压着不低于 0.30，避免黑方样本被饿死——反过来变成白崩。档位切换有 60 局的去抖（`DEBOUNCE`），防止在两档之间来回跳。

只看份额还不够，因为白赢样本本来就少，份额抬到 0.22 也抽不出东西。所以加了一个独立储库 `ww_reservoir`（`deque(maxlen=24000)`）：白赢样本除了进主 buffer，再单独存一份，采样时 `pools[2]` 直接换成整个储库。这样白赢样本不会因为主 buffer 是 10000 条的滑窗而被挤掉。实测主 buffer 里的白赢局面只有 696 条（约 7%），储库能脱离这个上限单独攒。

还有一道「反捡漏」：白胜但手数 < 20 的局，标签从 2 改成 3，不进白赢储库。理由是短手白胜多是黑方开局送，当作正样本会强化错误的策略。阈值走 `GOMOKU_WW_MIN_LEN`。

`handicap.json` 在这版里被固定成 `{'black_sims': 800, 'level': 0, 'note': 'disabled'}`。原先设想过给黑方减模拟量做不对称预算，实测证伪，留着文件只是让接口不报错。

### 到现在为止的三个危险信号

**一、白赢样本的供给极薄。** 93 局只出了 8 局白胜，手数分别是 24/46/52/28/14/10/24/34。其中 14 手和 10 手那两局被反捡漏划走，不算 W_win。真正进储库的只有 6 局约 120 个局面，乘 8 重增广≈960 条，`ww_res` 停在 832 就是这个量级。

现在每批强制抽 113 条 W_win，对着 832 条池子，单批覆盖率 13.6%。**同一个局面在相邻几批里反复被抽中**，实际上是把 6 局棋的 120 个局面当 22% 的训练信号在背。池子停涨就意味着供给见底。

**二、`ww_res` 从 14295 起就没再涨过**（600 → 696 → 832 → 832 → 832）。因为段 5 十三局全黑胜。这是结果不是原因，但它说明储库完全依赖白胜率，没有独立来源——白胜率一旦掉回 0，这个机制就空转。

**三、`ev_new` 又爬上来了。** 0.13 → 0.26 → 0.35 → **0.64** → 0.58，同时 loss 3.54 → 2.99。上面「能提前预警的指标」一节刚说过这两个在白崩时是反向指标。不过这次不能直接套：batch 里塞了 22% 白赢样本，value 头本来就不该再靠"猜黑赢"混分了，ev 短期抬高有一半是这个原因。**但配合段 5 白胜 0% 一起看，不能当好消息。**

`lr_multiplier` 还是 0.0878，还是卡在死区（降要 `kl>0.04 且 lr_mult>0.1`，升要 `kl<0.01`，实测 kl 0.049）。

### 判据（写在这里，事后不改）

窗口 3 个发行版本（约 120 局）。注意新版从 it13601 重开，`net_version` 从 0 重新计。

| 结论 | 条件 |
|---|---|
| 有效 | 白胜 ≥ 20%，均手 ≥ 24，速杀 < 15% |
| 无效 | 白胜仍 < 12%，或 `ww_res` 停在 1000 以下不涨 |
| 供给瓶颈（要调机制，不是调份额）| `ww_res` 持续 < 1000 时，降 W_win 份额或放宽 `GOMOKU_WW_MIN_LEN`（现 20） |

第二条是本轮新加的：**只盯白胜率会漏掉"数字涨了但棋没变强"**。白赢池子被反复抽样时，白胜率可以靠背那 6 局棋抬起来，而棋力没有变。判断依据不是白胜率，是池子大小和单批覆盖率。

第三条单独列，因为降份额和放宽阈值是两种不同的改法，别混着一起动。

#### 补记 2026-11-14 21:30：阈值不动，只修测量口径

窗口到期后做了一次储库体检（`docs/白赢储库体检_2026-11-14.md`，脚本 `tools/probe_ww_reservoir.py`），发现上面判据里的「`ww_res` 停在 1000 以下」**用错了量**：

- `ww_res` 是**条目数**（含 8 重 D4 对称增广），不是池子大小。实测 3136 条目 ⇒ 白走局面 392 个 ⇒ **D4 归一化后只有 368 个不同局面**。
- 等价换算：`ww_res` 1000 条目 = **125 个去重局面**。以后看「去重局面数」，别看条目数。
- **三个阈值（20% / 24 手 / 12%）一个字没动。**

到期复核（近 120 局）：白胜 13.3%（<20% ✗）、均手 18.2（<24 ✗）、速杀 38.3%（≤11 手，>15% ✗）、`ww_res` 3136 仍在涨 ✓ ⇒ **未达成"有效"**。
另外两项实测供后续参考：**92% 的白胜局是白自己造出活四**（样本真实性没问题），**单批 113 条只覆盖池子的 25%**（每局面中位被抽 5.6 次、最早那局 68 次）。

### 和前面几节的改动不在同一层

噪声位置（根先验 vs 采样）改的是搜索的探索方式，`c_puct` 改的是 PUCT 常数，这版改的是训练数据的构成。三条线互不替代：噪声位置决定能不能从饱和状态里爬出来，分层采样决定爬出来之后有没有正样本喂给它。`ch3` 那个结构性偏色入口没动，要治本还是得从零重训。

## 教训

1. **滚动平均会藏住 40 局一个版本的突变。** 判读必须先按 `net_version` 分组。
2. **loss 和解释方差在白崩时是反向指标。** 崩盘让局面变简单，预测自然变准。看到"指标全面向好 + 行为变短"要按警报处理。
3. **value 饱和会让所有 MCTS 参数失效。** 调 `c_puct`、调温度之前，先测根 Q 的跨度；跨度 < 0.05 时搜索已经名存实亡。
4. **`ch3`（执黑常量）是这个架构的偏色入口。** 网络能直接读出自己执黑执白，这是「身份捷径」的结构性来源。真要治本得改输入语义、从零重训，不在这一轮做。
5. **"白胜率提升"不等于"白棋变强"。** 分层采样强制往 batch 里塞白赢样本时，样本池本身很薄（93 局只有 6 局能进池），白胜率可以靠背这几局棋抬起来。判断依据要加池子大小和单批覆盖率，不能只看胜率。
6. **空盘 value 只覆盖一类崩法。** 它抓「把执黑当身份」，抓不到「空盘正常但中盘放弃防守」。后者的检查在必堵局面的走子上，`tools/probe_cpuct_defense.py` 能干这件事。
