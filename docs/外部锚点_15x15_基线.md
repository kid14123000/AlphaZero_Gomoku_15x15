## 4. 结论（写死，别事后改）

```
① 搜索预算不是瓶颈
   sims 400 → 800：执黑 5/9 → 4/9，逐盘 8/9 完全一致
   ⇒ 输的盘是"算不到正确着法"，不是"没算够"
   ⇒ 以后不要再靠加 sims 期待棋力提升

② 黑方 ≈ Rapfi depth5 水平
   执黑 44~56%（18 局 ±23pp）
   ⇒ 这是本网络目前唯一"能对外站住"的一面

③ 白方是碾压级差距，不是差一点
   两档共 18 局执白，全负（0/18）
   ⇒ 内部"白胜 8~20%"是相对自对弈的数，绝对水平上白方无法与 d5 抗衡
   ⇒ 任何"内部白胜率涨了"的结论，都必须回来在这 18 局上验证才算数

④ 内部指标与外部锚点的关系（双轨判据）
   · 内部白胜率 ↑ 但这里仍 0/18 ⇒ 可能只是"抓自己陪练的漏洞"
   · 只有这里也出现胜局，才算白方真实变强
```

## 5. 以后怎么用

```
对比条件（必须全同）：同 18 个开局 / 同 depth 5 / 同 sims 档 / 同 NNUE / 同 Rapfi 版本
判读口径：
  执黑胜局数变化 ≥2 局 才谈得上"有效"
  执白出现第 1 个胜局 = 白方跨过了一个台阶（历史性）
推荐节奏：每次结构级改动（空洞卷积 / 分色双网）后跑一次，作为期末考卷
```

## 6. 已知坑（本次踩过的）

```
① 随机首手会重复：两侧确定性 ⇒ 同一首手 = 同一盘棋
   首次跑 30 局随机首手，实际只有 7~8 个不同开局（"N 局 = 1 局"）
   ⇒ 必须 --fixed-openings
② batch 号跨 run 重复：新 run 从 batch_offset 重新编号
   同一个 batch 号在旧归档和新日志里是两盘不同的棋
   ⇒ 分析对局必须绑定日志文件路径，不能用 batch 号唯一索引
③ 长跑不要 | tail：输出会被缓冲到结束，全程看不见进度
   ⇒ 重定向到日志文件再轮询
```
