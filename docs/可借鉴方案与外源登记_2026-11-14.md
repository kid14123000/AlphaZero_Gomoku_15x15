## A1 ★★★ 用 value 筛选「平衡开局」（自适应开局池）

**出处**：AG `src/selfplay/OpeningGenerator.cpp`（`OpeningGenerator::generate`，约 44–56 行）+
`src/utils/misc.cpp::prepareOpening`（142–168 行）+ `src/selfplay/GameGenerator.cpp:25,73`。

```cpp
// OpeningGenerator.cpp
const float balance = std::fabs(iter->task.getValue().getExpectation() - 0.5f);
if (balance < (0.1f + 0.01f * trials)) {   // 只收 |V-0.5| < 0.1 的开局
    completed_openings.push_back(iter->moves);
    trials = 0;
} else trials++;                            // 不合格 → 丢弃重抽（阈值随 trials 缓慢放宽）
```

```cpp
// utils/misc.cpp::prepareOpening —— 开局本体：随机 0~15 手，中心加权
int opening_moves = std::max(minNumberOfMoves, randInt(6) + randInt(6) + randInt(6));  // 均值≈7.5
if (randInt(1000) == 0) opening_moves = 0;   // 1‰ 概率 0 手开局（完全交给模型）
```

**妙在哪（用户评价：这其实是自适应策略）**：
筛选器用的是**当前网络自己的 value**，不是人工写死的开局表。于是
- 网络弱时，只要"黑大优"的开局都会被丢掉 ⇒ 自动只留能打的局面；
- 网络变强后，同一个开局的估值会变，**被接受的开局集合自动迁移**，不需要人工维护开局池；
- 对自对弈还有一个附带效果：训练分布里不会出现"一边倒的开局"，`|V|≈0.5` 的局面天然样本均衡。

**和我们已试过方案的关系**：v36 做的是"前 3 手全随机"，**没有筛选** ⇒ 网络学成"抓坏开局直接速杀"、
白 1 节点从未被训练（v37 因此改回 `RANDOM_OPEN_MOVES=0`）。**A1 = v36 缺的那一步。**

**落地接口**：`worker_selfplay.py` 开局段（每局开始前）。改动不碰训练主循环、不碰采样。
**风险**：每局开局要跑一次 value 前向 + 可能重抽（重抽有上界，AG 用 `trials` 放宽阈值兜底）。
**判据（先写死）**：跑 150 局后 —— ① 均手 ≥24 ② 速杀≤11 手 <15% ③ 正常的"白胜率"不低于分层采样当前值（20%）。
若①②达成但③明显下降，说明筛掉了"白能赢"的开局，立即回退。
**状态**：`未做`（等拍板，需重启工兵）。

## A2 ★★ playout cap randomization（同局面多预算出标签）

**出处**：KG `configs/selfplay.cfg`

```
cheapSearchProb = 0.75          # 75% 的局面用便宜搜索
cheapSearchVisits = 50
maxVisits = 250                 # 训练时访问上限只有 250（不是 800）
reducedVisitsMin = 50
rootNumSymmetriesToSample = 4
useLcbForSelection = true; lcbStdevs = 5.0; minVisitPropForLCB = 0.15
```

**为什么对我们对症**：我们诊断出的白崩机制之一是「劣势局 value 学成一个确定值（±1 硬目标）→ 毒化白方 MCTS」。
同一局面在 50 / 250 两种预算下各出一次标签，价值目标自带"不确定性"，网络不会把"白必败"钉死。

**风险**：会直接破坏我们现有的诊断口径（`value_target=z`、局重复率、熵），上线前必须先想清楚怎么判读。
**状态**：`未做`。

## A3 ★★ 辅助目标：剩余手数头（`MovesLeftNetwork`）

**出处**：AG `src/networks/MovesLeftNetwork.cpp` + `include/alphagomoku/networks/MovesLeftNetwork.hpp`
（另有 `NNUE.cpp` 作为另一种轻量评估后端）。

**为什么对我们对症**：我们手工写了「短手白胜反捡漏」（`GOMOKU_WW_MIN_LEN=20`）来防止"速杀局把网络带偏"——
这正是因为没有"这局还要走多少手/局面有多复杂"的显式信号。加一个回归头（target = `episode_len - 当前手数`）
可以把这条启发式换成网络自己学的东西。
**状态**：`未做`。
